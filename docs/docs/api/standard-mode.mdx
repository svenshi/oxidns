---
title: 标准模式与后端边界
---

标准模式和专家模式仅是 WebUI 工作区。OxiDNS 后端不包含 Standard Intent 编译器、Plan、模板、Expert Copy 或模式所有权，所有 `/api/standard/*` 路由均不存在并返回 `404`。

## 数据流

```text
WebUI Standard Intent
  → TypeScript 迁移、校验、编译、Plan 与解释
  → 原生 OxiDNS YAML
  → POST /api/config/validate
  → POST /api/config/apply
  → DNS Runtime
  → 原始查询事件
  → WebUI query-explainer
```

前端从 `GET /api/build` 获取当前二进制的 Feature、Server、Executor、Matcher 和 Provider 能力。它生成确定性 YAML 和 Intent revision，但后端的真实配置校验始终是 Apply 的最终条件。

## 使用的通用接口

| 用途 | 接口 |
| --- | --- |
| 候选 YAML 校验 | `POST /api/config/validate` |
| 原子应用与回滚 | `POST /api/config/apply` |
| 事务状态 | `GET /api/config/apply/status` |
| 健康 YAML 历史 | `GET /api/config/history` |
| 历史 YAML 预览 | `POST /api/config/history/restore` |
| 透明工作区 JSON | `GET/PUT /api/webui/config` |
| 构建与插件能力 | `GET /api/build` |

完整事务字段见[配置接口](configuration.mdx)。

## 工作区状态

活动 Intent、生成映射和最近生成信息可作为普通 JSON 保存在 `/api/webui/config`。后端只提供 2 MiB 透明 CAS 存储，默认值是 `{"schema":1}`，不会解析其中的 Standard 或 Expert 字段。

DNS Apply 成功后，WebUI 最多重试三次工作区 CAS。即使工作区保存失败，已经生效的 DNS 配置也不会回滚；界面会提示下载 Intent 以便恢复工作区。

模板位于浏览器 IndexedDB，按 OxiDNS 实例隔离，最多 64 条且累计最多 2 MiB。Intent 导入导出、模板预览、Expert Copy 和 Expert Analysis 均在浏览器完成。Expert Copy 只把生成 YAML 放入编辑器，不写配置。

## 查询解释

Query Recorder 后端只返回记录、步骤、截断统计和任意只读 `context` 字符串映射。Cache、Forward 与 Fallback 都是原始运行事件；后端不返回产品化 `diagnosis`，也不解释 `intentRevision`。

WebUI 只有在记录中的 revision 与活动 Intent 及生成映射匹配时才添加产品解释。版本不一致或映射缺失时，仅显示后端提供的原始事实。
