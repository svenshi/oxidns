---
title: Standard Mode and Backend Boundary
---

Standard and Expert are WebUI workspaces only. The OxiDNS backend contains no Standard Intent compiler, Plan, templates, Expert Copy, or mode ownership. Every `/api/standard/*` route is absent and returns `404`.

## Data flow

```text
WebUI Standard Intent
  → TypeScript migration, validation, compilation, Plan, and explanation
  → native OxiDNS YAML
  → POST /api/config/validate
  → POST /api/config/apply
  → DNS Runtime
  → raw query events
  → WebUI query-explainer
```

The client obtains Feature, Server, Executor, Matcher, and Provider capabilities from `GET /api/build`. It produces deterministic YAML and an Intent revision, while backend validation of the native configuration remains the final Apply gate.

## Generic APIs used by the workspace

| Purpose | Endpoint |
| --- | --- |
| Candidate YAML validation | `POST /api/config/validate` |
| Atomic apply and rollback | `POST /api/config/apply` |
| Transaction status | `GET /api/config/apply/status` |
| Healthy YAML history | `GET /api/config/history` |
| Historical YAML preview | `POST /api/config/history/restore` |
| Opaque workspace JSON | `GET/PUT /api/webui/config` |
| Build and plugin capabilities | `GET /api/build` |

See [Configuration API](configuration.mdx) for complete transaction fields.

## Workspace state

The active Intent, generated mappings, and latest generation metadata may be stored as ordinary JSON through `/api/webui/config`. The backend provides only a 2 MiB opaque CAS store whose default is `{"schema":1}`; it does not parse Standard or Expert fields.

After DNS Apply succeeds, the WebUI retries workspace CAS up to three times. A workspace save failure never rolls back the active DNS configuration; the UI offers an Intent download for workspace recovery.

Templates live in browser IndexedDB, scoped by OxiDNS instance, with a limit of 64 records and 2 MiB total. Intent import/export, template preview, Expert Copy, and Expert Analysis are browser operations. Expert Copy only places generated YAML in the editor and never writes configuration.

## Query explanation

The Query Recorder backend returns only records, steps, truncation statistics, and an arbitrary read-only `context` string map. Cache, Forward, and Fallback entries are raw runtime events. The backend returns no product-level `diagnosis` and does not interpret `intentRevision`.

The WebUI adds product explanations only when the recorded revision matches the active Intent and generated mapping. If the versions differ or mapping is unavailable, it displays the raw backend facts only.
