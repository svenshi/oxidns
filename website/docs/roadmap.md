# 路线图

本页只记录尚未完成的方向。已经发布的能力和迁移说明归档在[版本更新](releases.md)；具体工作项以 GitHub Issues、Pull Requests 和实际 release 为准。

路线图用于表达优先级，不构成发布日期或兼容性承诺。项目可能根据稳定性、安全、性能回归和社区反馈调整顺序。

## Now — 正在推进

### 标准模式 WebUI

为不希望直接编写 YAML 的用户提供表单化配置入口。去广告、防污染、家庭过滤和分流加速等常见场景通过表单、开关和模板完成，同时保留进入高级模式编辑完整规则的路径。

当前重点是让标准模式生成的配置可解释、可校验、可安全切换，并避免为了简化界面而削弱底层 `sequence` 策略模型。

## Next — 下一批目标

### 插件管理 API 与 WebUI 接入

按照“个体枚举、状态查询、动作触发归 API；计数器、直方图、低基数 gauge 归 metrics”的边界，逐步补齐 `forward`、`cron`、`download`、`script`、`ip_selector`、`cache`、`rate_limiter` 等插件的运行时管理能力，并在 WebUI 详情面板接入对应端点。

每项 API 会同时评估访问控制、返回数据规模、热路径开销、可选 feature 和向后兼容性，不以端点数量作为完成标准。

## Later — 中长期方向

### Cache 架构与性能

拆分查询、准入、TTL 决策、lazy refresh、淘汰维护、持久化和指标边界；重点降低命中路径的消息复制、临时分配、时间戳写放大和锁竞争，并补充大容量与并发刷新 benchmark。

### DHCP 与本地 DNS 联动

探索可选 DHCP 服务，覆盖地址池、静态租约、租约持久化和常用 options。租约 hostname/IP 通过明确数据接口提供给 DNS 策略，DHCP runtime 不直接耦合到 DNS 请求热路径。

### 第三方插件生态

- 探索 WebAssembly 插件，以稳定接口和沙箱隔离支持独立分发。
- 探索原生动态库插件，服务对延迟和吞吐要求极高的场景。
- 在开放第三方 ABI 前，优先稳定配置模型、生命周期、能力声明、资源限制和故障隔离语义。

## 如何参与

在实现或认领路线图项目之前，请先阅读[贡献指南](contributing.md)，并通过 GitHub Discussion 或 Issue 对齐问题、边界与验收方式。提案应说明用户场景、配置/API 影响、性能与安全风险、跨平台范围和迁移策略。
